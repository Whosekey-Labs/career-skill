# 4. 자소서 초안 → 내 구글 문서

입력: 프로필(경험 소재·글 스타일·내 요청사항) + 3단계 요건 정리. 3단계가 없으면 공고만 읽고 문항·AI 규정부터 확인한다.

## 0) 쓰기 전 확인

- 공고를 한 번 더 열어(`career.py job` 또는 브라우저) 마감이 지나지 않았는지, 문항·글자 수가 바뀌지 않았는지 본다. 마감됐으면 먼저 알린다.
- **AI 사용 규정이 "금지"면 초안을 쓰지 않는다.** "이 공고는 AI 작성을 금지해요. 직접 쓰신 초안을 주시면 고칠 점만 알려 드릴게요."로 안내하고 5)의 첨삭 흐름으로 간다. 탐지기 우회는 하지 않는다.
- 블라인드 채용이면 학교·지역·가족·나이 정보를 쓰지 않는다.

## 1) 문항 해석과 경험 배분 (사용자에게 짧게 보여 준다)

1. 문항마다 "이 문항은 ○○를 보려는 것으로 봤어요" 한 줄. 하위 질문이 있으면 나눠 적는다.
2. **문항-경험 배분표**: 프로필 "경험 소재"에서 문항마다 쓸 경험을 고른다. 같은 경험이 두 문항에 겹치지 않게 한다.
3. 꼭 필요한 빈칸만 **한 번에 최대 3개** 묻는다. 특히 지원동기는 "이 회사를 어떻게 알게 됐는지, 직접 써 봤거나 끌린 점"을 꼭 묻는다(AI가 가장 많이 지어내는 곳이다). 사용자가 "그냥 써줘"라고 하면 `[직접 입력]`으로 비우고 쓴다.

경험 소재가 애매하면 아래 4가지를 확인한다(수치를 먼저 제시하고 "맞죠?"로 유도하지 않는다).
- 내가 한 일인가, 팀이 한 일인가
- 결정했나, 제안했나, 실행했나
- 숫자는 잰 값인가, 기억으로 어림한 값인가 → 어림이면 `[추정]` 표시
- 그때의 판단인가, 지금 돌아본 해석인가

## 2) 구성

- 공고 문항과 글자 수를 **그대로** 따른다. 문항이 없으면:
  - 신입·일반: 지원동기 / 직무 역량·경험 / 성장 과정 / 입사 후 포부
  - 경력직: 지원동기 / 경력 기술(프로젝트·성과) / 입사 후 기여
- 1,000자 이하 문항은 경험 1개, 1,200자 이상이면 2개까지.
- 첫 문장은 50자 안팎으로 결론부터(두괄식).
- 경험은 상황 → 내 행동 → 결과(숫자) 순서로 쓰되 "상황은 / 결과는" 같은 이름표는 붙이지 않는다.
- 회사 이야기는 **지원동기·포부에만**, 3단계 접점 사실표에 있는 것만 쓴다. 경험 문항은 마지막 문장에서 "공고의 수행업무 + 내 경험의 방법"으로 잇는다.
- 문항마다 마지막 문장의 시작과 끝맺음을 다르게 한다.

## 3) 쓰는 법

- 프로필 "글 스타일"을 따른다. 없으면 격식체(~했습니다).
- **숫자·사례는 프로필·사용자 답변에 있는 것만.** 없으면 `[직접 입력: 예) 처리 건수 몇 건]`. 반올림·과장하지 않는다.
- 연차·경력 차이를 스스로 깎지 않는다. 묻지 않은 약점은 쓰지 않는다.
- 경험이 없는 주제는 본문 뒤 "## 바꿔 끼울 문단"에 "경험 있음 / 경험 없음" 두 문단(150~300자). "경험 없음"은 공부하겠다는 약속 대신 "도구는 달라도 같은 구조의 일을 이렇게 했다"처럼 인접 경험으로 닫는다.
- **쓰지 않는 표현**: 최선을 다해, 열정을 가지고, 값진 경험, 많은 것을 배웠습니다, 시너지, 기여하겠습니다, 함께 성장하겠습니다, "~라고 믿습니다"로 끝맺기, "신뢰는 ~에서 나옵니다" 같은 일반론, 업계를 선도하는·혁신적인 같은 회사 칭찬형 도입, "저는 ~한 사람입니다"로 시작하기, ~에 있어서·~되어졌습니다 같은 번역투, 다각적·체계적·혁신적 남발, "입사 전까지 ○○을 공부하겠습니다".
  - 단, "그래서", "또한", "~를 통해", "저는"은 자연스러우면 쓴다. 금지 목록을 늘리지 않는다.

## 4) 다 쓴 뒤 점검 (보여 주지 않고 고친다)

- **치환 테스트**: 회사명을 경쟁사로 바꿔도 말이 되는 문장, 지원자를 다른 사람으로 바꿔도 말이 되는 문장은 다시 쓴다. 다시 쓸 때도 사용자에게 받은 사실만 쓴다.
- **글자 수**: 문항 제한의 90~100%. 기준(공백 포함/제외)을 공고대로, 모르면 공백 포함. 줄바꿈 몫으로 10~20자 여유. 직접 세지 말고 `python3 career.py count -i 초안.md`로 잰다(스크립트 모드가 아니면 네 도구로 정확히 센다). 사실이 모자라 못 채우면 억지로 늘리지 말고 필요한 정보를 질문으로 낸다.
- **문항 체크**: 1)에서 나눈 하위 질문마다 답한 문장이 있는지.
- 프로필 "내 요청사항"을 지켰는지.

## 5) 첨삭 흐름 (사용자가 직접 쓴 초안을 줄 때)

새로 쓰지 않는다. 사용자가 강조하려던 점은 지키고 최소한만 고친다.
```
- 살린 핵심: …
- 고친 곳: 원래 → 수정 (이유 한 줄), 3~6개
- 줄인 부분: …
- 확인 필요: 숫자·사실 중 근거가 안 보이는 것
```

## 6) 형식

```markdown
# {회사명} {포지션} 자기소개서 초안

## 1. 지원 동기 (공백 포함 512자 / 제한 600자)
…

## 2. 직무 역량 (공백 포함 731자 / 제한 800자)
…

## 바꿔 끼울 문단
### 데이터 분석 — 경험 있음 / 경험 없음
…

## 문항 체크
- ① 왜 이 회사 → 1번 첫 문장 / ② 왜 이 직무 → 1번 셋째 문장 …

## 예상 면접 질문
- (이 초안을 읽은 면접관이 물을 꼬리질문 2~3개)
```

## 7) 결과물 주기 (사용자 본인 계정에)

문서 제목: `자소서_{회사명}_{포지션}` (분석은 `분석_{회사명}`)

1. **구글 문서 (1순위)**: 구글 문서·드라이브 도구가 있으면 사용자 드라이브에 구글 문서로 만들고 링크를 준다.
2. **연결 유도**: 0단계에서 구글을 연결하지 않았고 거절한 적도 없으면 한 번 더 권한다(방법은 `guides/00-connect.md`). 피클은 구글 앱을 연결하면 구글 문서를 만들 수 있다.
   - "자소서를 내 구글 드라이브에 문서로 바로 만들어 드릴게요. 구글 계정 연결이 한 번 필요해요. 지금 연결해 볼까요? (30초면 돼요. 안 해도 파일로 드려요)"
   - 거절하면 3번으로 주고 다시 권하지 않는다.
3. **파일**: 네 문서 만들기 기능으로 워드(.docx)나 PDF.
4. **채팅 본문**: 파일도 못 만들면 본문 그대로.

캘린더가 연결돼 있으면 마감일을 "[마감] {회사명} {포지션}"으로 등록하고 한 줄로 알린다.

마지막 안내 (두 줄):
- "`[직접 입력]`·`[추정]` 칸은 실제 내용으로 채워 주세요. AI 초안은 뼈대고, 내 경험이 들어가야 합격 자소서가 돼요."
- "더 짧게, 첫 문장 바꾸기, 말투 부드럽게 같은 수정도 말씀만 하세요."
