# 1. 프로필 + 직군·검색할 사이트

목표: 첫 공고를 빨리 보여 줄 만큼만 묻고 기억에 저장한다. 다음부터는 다시 묻지 않는다.
온보딩에서는 **1)과 2)만** 한다. 3)은 회사 분석·자소서 단계에서 필요할 때 한다.

## 1) 최소 프로필 (온보딩, 질문 2~3번)

- 사용자의 첫 메시지에 이미 있는 것은 묻지 않는다(예: "이직 준비"라고 했으면 상태는 묻지 않는다).
- 한 메시지에 묶어 짧게 묻는다:
  "어떤 일을 찾으세요? 직무, 지역, 경력(신입/몇 년 차), 원하는 조건(정규직·급여 등)을 편하게 말씀해 주세요."
- 신입·현장직(간호조무사·생산직·조리·미용·운전 등)은 급여를 연봉 대신 **월급·시급**으로, 조건에 **근무 가능 시간·교대 가능 여부**를 묻는다.
- 빠진 것만 한 번 더 묻는다. 모르면 넘어가도 된다고 말한다.
- 채용 사이트 로그인이 연결돼 있으면 등록된 이력서를 불러와 채운다(묻는 횟수가 줄어든다).

## 2) 직군과 검색할 사이트 (온보딩, 질문 1번)

1. `guides/jobs/index.md`를 열어 사용자 직무에 맞는 직군 파일 **하나**를 고르고 연다(세부 직무·검색 키워드·사람인 직무 코드·전문 사이트).
2. 그 직군에서 쓸 사이트를 **추천 5~6곳**으로 추린다.
   - **빠르게 찾는 곳(스크립트) 3~4곳**: `python3 career.py sites`에 키가 있는 사이트만 여기에 넣는다(직군 파일 `스크립트:` 줄 + 아래 기본 조합).
   - **직접 열어 보는 전문 사이트(브라우저) 1~2곳**: `sites`에 키가 **없는** 사이트만. 직군 파일 "어디서 찾나"에서 `(스크립트: 키)` 표시가 없는 곳 중 사용자 세부 직무에 가장 맞는 곳. 직군 파일에 이런 사이트가 있으면 **최소 1곳은 반드시 넣는다.**
   - 스크립트로 되는 사이트를 "직접 열어 보는 곳"에 넣지 않는다(예: 랠릿·링크드인은 스크립트다).
3. 사용자에게 짧게 보여 주고 고르게 한다. 예:
   "○○ 직군은 이런 곳에서 공고를 찾아요.
   - 빠르게 찾는 곳(추천): 사람인, 잡코리아, 원티드, 리멤버
   - 직접 열어 보는 전문 사이트(추천): 베이크잡
   - 더 볼 수 있는 곳: 푸드앤잡, 요리사잡, 알바천국 …
   빠르게 찾는 곳은 사용량이 적게 들고, 직접 열어 보는 곳은 조금 더 들어요. 안 보실 곳은 빼고, 더 보실 곳은 말씀해 주세요. 그냥 '좋아'라고 하시면 추천대로 할게요."
   - 사용자가 빼라고 하지 않은 사이트를 에이전트가 임의로 빼지 않는다(사용량을 아끼려는 이유로도).
4. 고른 결과를 프로필의 "직군과 검색할 사이트"에 저장한다. 다음부터 공고 찾기·매일 알림은 이 목록만 쓴다.
5. 나중에 "○○도 같이 봐줘", "○○는 빼줘", "검색할 사이트 보여줘"라고 하면 바꾸거나 보여 준다.
6. 마무리 한 줄 후 2단계로: "설정 끝났어요. 바로 맞춤 공고 찾아볼게요."

기본 조합 (`--sites` 값):
- 기본: `saramin,jobkorea`
- IT·기획·디자인·마케팅: `+wanted` / 개발자: `+jumpit`
- 경력직·헤드헌팅: `+remember`
- 대기업·공기업 신입 공채: `+jasoseol`
- 금융·증권·운용: `+kofia` / 리츠·부동산 운용·개발: `+kareit,kofia`
- 공공기관: `alio` / 공무원 임기제·경력경쟁·공무직: `gojobs` / 해외: `worldjob`
- 현장직·중장년·지역 중소기업: `+work24`

## 3) 경험·자료 받기 (회사 분석·자소서 단계에서, 처음 한 번)

1. 가진 자료부터 받는다:
   "예전에 써 둔 이력서·경력기술서·자기소개서가 있으면 주세요(파일, 링크, 붙여넣기 다 돼요). 회사가 달라도 괜찮아요. 거기서 경험과 말투를 뽑아 두면 새 글이 내 글에 가깝게 나와요."
   - 구글 드라이브가 연결돼 있으면 "드라이브에서 '자기소개서', '이력서' 문서를 찾아볼까요?"라고 묻고, 허락하면 목록을 보여 준 뒤 고른 것만 읽는다.
2. 자료가 없거나 부족하면 필요한 것만 묻는다(한 번에 최대 3개):
   - 경력: 회사·기간·맡은 일 (신입이면 전공·실습·인턴·프로젝트·대외활동)
   - 성과: 숫자로 말할 수 있는 것 (신입·현장직이면 실습 기관, 다룬 장비·업무, 자격증, 근무 가능 시간)
   - 자격증·어학·툴
3. 예전 자소서가 있으면 두 가지를 뽑는다(원문 전체는 저장하지 않고 요약만).
   - **경험 소재**: 에피소드마다 한 줄(상황·내 역할·행동·결과). 같은 경험은 하나로 합친다.
   - **글 스타일**: 말투(~했습니다/~했어요), 문장 길이, 자주 쓰는 표현·첫 문장 습관, 사용자가 싫어할 만한 표현.

## 4) 저장 형식

정리해 보여 주고 "맞나요?" 한 번만 확인한 뒤 기억에 저장한다. 아래는 **형식만 보여 주는 틀이다. `{ }` 안은 사용자에게 받은 값으로만 채우고, 받지 못한 칸은 비워 둔다.**

```markdown
## 프로필
- 상태: {신입 / 재직 중 이직 / 쉬는 중}
- 희망: {직무} / {산업} / {지역} / {연봉·월급·시급 하한} / {고용형태}
- 경력: {회사} ({기간}) {직무} — {맡은 일}
- 성과: {지표: 전 → 후 (기간)}
- 기술·자격: {자격증·툴}

## 경험 소재
- [{주제}] {상황} → {내 행동} → {결과}

## 글 스타일
- 말투: {~했습니다 / ~했어요}, 문장 {짧게/길게}
- 습관: {예: 첫 문장에 결과}
- 피할 것: {사용자가 싫어하는 표현}

## 직군과 검색할 사이트 (1단계에서 정함)
- 직군: {번호 이름} (파일 `guides/jobs/{파일명}`)
- 스크립트: {키 목록}
- 브라우저: {사이트 이름}

## 내 요청사항 (결과 내기 전에 항상 확인)
- 공고: {예: 판교·분당만}
- 자소서: {예: 항목당 500자 이내}
- 알림: {예: 아침 8시}
```

## 규칙

- **경력 연차는 날짜로 계산한다.** 문서 표지의 "○년 차"를 그대로 믿지 않고, 첫 실무 시작일(년·월)을 확인해 오늘 기준으로 계산한 뒤 사용자에게 한 번 확인한다.
- **칭찬·과장하지 않는다.** "완벽합니다", "당연히 받을 수 있어요", "독보적인" 같은 말을 쓰지 않는다. "강점 한 줄"은 자료에 있는 사실로만 쓴다("소통 로스 0%"처럼 근거 없는 수치 금지).
- **비공개 자료는 쓰기 전에 묻는다.** 깃헙 비공개 저장소, 사내 문서, 고객사 이름처럼 공개되지 않은 내용은 프로필에 "(비공개)"로 표시하고, 자소서·이력서에 넣기 전에 "이건 공개해도 되는 내용인가요?"라고 확인한다.

- 사용자가 말하지 않은 경험·숫자는 채우지 않는다. 빈 칸은 비워 둔다.
- 주민등록번호·주소·연락처·가족사항 같은 민감 정보는 자료에 있어도 프로필에 옮기지 않는다.
- 자료는 나중에 더 받아도 된다. "예전 자소서 더 줄게"라고 하면 경험 소재·글 스타일에 더하고 겹치는 건 합친다.
- "프로필 바꿔줘"라고 하면 바뀐 부분만 고쳐 다시 저장한다.
- "내 요청사항"은 처음엔 비워 둔다. 계속 적용될 요청이 올 때마다 맞는 줄에 짧게 더하고, 반대되는 새 요청이 오면 옛 것을 바꾼다. "내 요청사항 보여줘·지워줘"에 따른다.
